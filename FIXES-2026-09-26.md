# Life Launcher bug-fix source revision

This archive contains patched source, not compiled Windows EXE or Linux AppImage binaries.

## Changes

- Mouse Trail draws at the end of Screen.renderWithTooltip instead of Screen.render. Custom menus no longer cover it. Existing enabled/disabled preference and custom colour, length, size and rainbow options are preserved.
- Main-menu button hitboxes use their last rendered position during the entrance animation.
- Motion blur decodes the exact 128/255 neutral point, normalizes turn velocity and smoothing against elapsed time, and resets after long render gaps. It releases the post-effect slot in menus. Upload failures now leave a diagnostic and retry.
- Recording pads native odd dimensions for H.264, resamples frames after a window resize, isolates writer sessions on immediate restart, and returns to IDLE with the encoder log on a broken pipe.
- Wallpaper gradient tint is now separately opt-in (Settings > Appearance > Tint wallpaper), with a true zero strength. It defaults off, preserving source-image colours. This does not recolour the source wallpaper itself.
- Linux uses an unshaped native window to avoid the existing code's documented XWayland repaint-offset issue. The window has a minimum usable size; sidebar profile scrolling is clamped after resize.
- Windows and Linux package scripts stop on client build failure and clean launcher resources before packaging, avoiding stale bundled client files. Windows captures the client build log in build/client-build.log.

## Verification performed

Shared common Java sources compiled successfully through the installed JDK compiler module (Java 17). Executed checks passed for stationary blur, equivalent 60/120 FPS camera motion, render-gap reset, FFmpeg recording at 321x241 (encoded at 322x242), resizing, pause/resume, immediate stop/start, and encoder failure recovery. ffprobe confirmed valid MP4 streams. Linux shell syntax passed.

Run `bash checks/run.sh` with a JDK and ffmpeg installed to repeat the common-code checks.

## Remaining verification / limitations

The environment could not download Gradle and had no Java 21 installation. Therefore the complete launcher and Fabric client have NOT been compiled, launched or visually tested here. Windows 10/11 executable compatibility and Linux AppImage execution are NOT verified. The screenshot's client-build failure cannot be diagnosed from the summary line alone; build/client-build.log (or build/client-errors.txt) is needed. These source fixes must not be represented as a fully tested release or a guarantee that every bug is resolved.

The sidebar repaint mitigation and wallpaper colour settings need confirmation using the original animated wallpaper on the affected desktop. In-game shader loading and mouse-trail ordering also need a Minecraft 1.21.11 runtime check.

## Separate platform builds

Linux, full JDK 21 and network access:

    bash build-appimage.sh --no-install

Output: LifeLauncher-x86_64.AppImage

Windows 10/11 x64, full JDK 21 and network access:

    build-windows.bat

Portable output: dist\Life Launcher\Life Launcher.exe
Keep its entire containing folder, including its bundled runtime. The standalone installer EXE is produced only when WiX Toolset 3 is installed. Windows packaging must run on Windows; the Linux build produces the AppImage separately.

If the client fails, send build/client-build.log. Both scripts now stop instead of silently producing a launcher without Life Client.
